Design Documentation

A full technical and design rationale for the NEXVOLT 3D Product Viewer — covering modelling, lighting, accessibility, interaction design, and performance.

01

Modelling Choices

Three Geometrically Distinct Models

The assignment requires at least three 3D models with different geometry. Each NEXVOLT product was designed with a distinct mesh topology to demonstrate variety in both shape and construction technique:

Slim Energy Can

Cylindrical body with a bevelled shoulder taper, recessed neck, and dome-base geometry typical of food-grade aluminium cans. Loop topology on the waist allows clean edge-loop subdivision without pinching. Approx. 4 000 triangles. Material: brushed aluminium (metalness 0.95, roughness 0.28).

Sport Bottle

Organic contoured surface modelled with Subdivision Surface modifier then applied. The flip-cap is a separate mesh for independent material assignment. Frosted body uses Principled BSDF with Transmission = 0.35, Roughness = 0.65 to simulate semi-opaque HDPE plastic. Approx. 8 000 triangles.

Crushed Can

Derived from the slim can base mesh. A Proportional Editing deformation pass followed by freeform sculpting (Grab brush) simulates real aluminium buckling — the deliberately chaotic, irregular geometry demonstrates the viewer’s ability to handle non-uniform meshes. Approx. 6 500 triangles.

Why GLB (Binary GLTF)?

  • Single binary file — textures, geometry, and PBR material data are embedded in one HTTP request, avoiding the multi-file round-trips required by OBJ + MTL.
  • PBR-native — GLTF 2.0’s Metalness/Roughness material model maps directly to MeshStandardMaterial in THREE.js with no conversion layer.
  • Compact — binary encoding is typically 30–40 % smaller than ASCII OBJ for identical geometry. Optional Draco compression reduces it by a further 60–80 %.

Where to Place the GLB Files

The models are stored inside the project’s assets/models/ folder. Place the three exported files at:

  • assets/models/nexvolt_slim_can.glb
  • assets/models/nexvolt_bottle.glb
  • assets/models/nexvolt_crushed.glb

Blender Export Guide

  1. Apply all modifiers and transforms: Object → Apply → All Transforms.
  2. Select the objects to export.
  3. File → Export → glTF 2.0 (.glb/.gltf).
  4. Format: glTF Binary (.glb).
  5. Enable: Selected Objects, Apply Modifiers, UVs, Normals, Vertex Colors, Materials.
  6. Under Geometry: enable Apply Modifiers if not already applied.
  7. Optional: enable Draco mesh compression for smaller files (requires DRACOLoader in the THREE.js loader setup).
  8. Click Export glTF 2.0.
Run through a local server. Opening index.html directly as a file:// URL blocks the browser’s fetch() API. GLTFLoader will silently fail. Use VS Code Live Server, python -m http.server, or npx serve . from the project directory.
02

Lighting Setup

Four-Point Studio Rig

The scene uses a classic product-photography lighting setup implemented with THREE.js DirectionalLight and AmbientLight:

Ambient (0.5×)

Omnidirectional baseline that prevents surfaces in shadow from going completely black. Intensity is deliberately low to preserve contrast — higher values flatten the perceived 3D form.

Key Light (2.0×, warm)

Main light from upper-right (4, 9, 5). Warm tint (#fff8f0) simulates a tungsten studio softbox at a 45° angle — the standard “Rembrandt” position for crisp highlights on metallic surfaces.

Fill Light (0.6×, cool)

Cool blue-white (#f0f5ff) from the left (−5, 3, −2). Complementary colour temperature to the warm key, keeping shadow areas from looking muddy while preserving depth.

Rim Light (1.0×, white)

Pure white back-light from directly behind (0, 5, −7). Creates the bright edge highlight that separates the product from the dark background — a hallmark of premium commercial product photography.

PMREM Image-Based Lighting

A PMREMGenerator converts a hand-painted equirectangular canvas panorama into a pre-filtered environment cube map. This provides physically-correct specular highlights and reflections via Image-Based Lighting (IBL) at zero runtime cost — the map is baked once during scene initialisation and the generator is disposed immediately to free GPU memory.

The canvas panorama depicts a dark studio ceiling (gradient grey) with two additive soft-box patches — warm key-side and cool fill-side — so metallic surface reflections remain visually consistent with the scene’s direct light rig.

ACES Filmic Tone Mapping

THREE.ACESFilmicToneMapping with toneMappingExposure = 0.95 applies the Academy Color Encoding System’s filmic contrast curve to the HDR render buffer. This preserves metallic highlight detail (avoiding blown-out hotspots), lifts shadows for visibility, and produces the warm-contrast look of cinema rather than the flat output of linear tone mapping.

Per-Load Material Enhancement

After each GLB loads, every mesh is traversed and its material adjusted: envMapIntensity = 0.55 controls how strongly the studio environment contributes to reflections. For already-metallic surfaces (metalness > 0.35), roughness is clamped to the 0.22–0.40 brushed-aluminium range — sharp enough for distinct highlights, soft enough to avoid a mirror-like look.

03

Accessibility — WCAG 2.1 AA

Perceivable

  • Text alternatives — every interactive element has an aria-label describing its action. All decorative elements carry aria-hidden="true" so screen readers skip them.
  • aria-live="polite" on the loading overlay means screen readers announce model-loading status without interrupting the user’s current reading.
  • Colour contrast — all body text meets the 4.5:1 minimum ratio. The red accent on dark backgrounds meets the 3:1 large-text threshold.

Operable

  • Skip link — a “Skip to main content” link appears on first Tab keypress, bypassing the header and landing focus inside the 3D viewer region.
  • Focus indicators — :focus-visible shows a 2 px red outline on keyboard-navigated elements only; mouse users never see it.
  • Touch targets — on screens ≤ 600 px all buttons receive a minimum height of 44 px (WCAG 2.5.5). The 300 ms iOS tap delay is removed via touch-action: manipulation.
  • ARIA landmarks — role="banner", role="main", role="region", and role="contentinfo" allow screen-reader users to jump directly between page sections.

Understandable

  • Toggle semantics — wireframe, auto-rotate, lights, glow, and ambient buttons all use aria-pressed to communicate on/off state. The visible text label also changes to match (e.g. “Wireframe” ↔ “Solid Mode”).
  • Range slider — the intensity input has explicit aria-valuemin, aria-valuemax, and aria-valuenow attributes. The adjacent value display uses aria-live="polite" so the number is announced after each adjustment.

Robust

  • prefers-reduced-motion — detected once at startup. When true: page fade-in animation is suppressed; hero decorative circles are stopped; the floating model animation is disabled (model stays stationary); all scroll-triggered fade/slide transitions are bypassed so elements start fully visible.
  • Semantic HTML5 elements (<header>, <main>, <section>, <article>, <footer>, <nav>) provide meaningful document structure without relying on ARIA overrides.
04

Interaction Design

Orbit Controls with Damping

OrbitControls with enableDamping = true and dampingFactor = 0.05 adds physical inertia to camera movement — releasing a drag continues the motion briefly before settling. This is a standard technique from game cameras that gives the viewer a premium, “physical” feel. Polar angle limits (maxPolarAngle = 0.8π, minPolarAngle = 0.1π) prevent the camera from going below the ground plane or directly overhead.

Floating Animation

The model gently hovers on a sine wave: sin(t × 0.45) × 0.022. This is a common product-landing-page technique that adds a sense of “life” to an otherwise static object. The amplitude (0.022 world units) and frequency (0.45 rad/s ≈ one cycle per 14 s) were tuned so the motion is subliminal — felt but not consciously noticed. The drop shadow inversely scales with float height, reinforcing the physical illusion.

Smooth Camera Reset

“Reset Camera” does not snap — it sets an isCameraResetting flag that the animation loop polls each frame. When active, the camera lerps toward the default position with factor 0.07, reaching it in approximately 0.5 s at 60 fps. A controls.addEventListener('start') listener cancels the lerp the moment the user grabs the camera, preventing the animation from fighting user input.

Rim Glow Shader — Custom GLSL (Deeper Understanding Feature)

Activating the Glow button applies a custom GLSL shader to every mesh in the model. The shader renders a THREE.BackSide copy of each mesh at 1.12× scale, tinted red using the Fresnel rim formula:

float rim = 1.0 - abs( dot( normalize(vNormal), normalize(vViewPosition) ) );
rim = pow( rim, glowPower );
gl_FragColor = vec4( glowColor * rim, rim );

The dot product between the surface normal and view direction is 1 at surfaces facing the camera (no glow) and approaches 0 at grazing angles (maximum glow), producing the characteristic rim-lighting silhouette. AdditiveBlending composites the glow without clipping — it adds light energy, never darkens. Glow meshes are attached as children of their parent meshes so they inherit transforms automatically; they are disposed on model swap or toggle-off to prevent GPU memory leaks.

Audio Feedback

All buttons play a short synthesised tone via the Web Audio API, created lazily on first user interaction (browser autoplay policy). Two tones exist: a high-pitched tick (900 Hz, 70 ms) for general buttons, and a rising two-note glide (360→720 Hz, 220 ms) for model switches. The Ambient Sound toggle activates a continuous atmospheric hum from three oscillators (38 Hz sawtooth + 76 Hz sine + 114 Hz triangle) filtered through a 220 Hz lowpass, fading in over 1.8 s to avoid a jarring onset.

Model Gallery & Scroll Animations

The gallery “Load in Viewer” buttons call the same switchModel() function as the control-panel buttons and programmatically scroll the viewer back into view. Product and gallery cards use IntersectionObserver to trigger a CSS fade-up transition when they enter the viewport (threshold 12 %), with a 120 ms stagger per card for a cascading reveal effect. The observer unregisters each element after its first trigger so the animation runs exactly once.

05

Performance Optimisations

Pixel Ratio Cap (2×)

Math.min(window.devicePixelRatio, 2) — a 3× DPR phone would render 9× the pixels of a 1× screen for no visible gain above 2×. Re-evaluated on every resize in case the window moves to a different monitor.

Page Visibility API

When the tab hides, cancelAnimationFrame(animFrameId) stops the render loop entirely. On restore, clock.getDelta() discards the accumulated hidden time, preventing a time-jump that would snap the float animation.

PMREM Disposal

The PMREMGenerator and its source equirectangular texture are disposed immediately after the environment map is baked, freeing GPU shader programs and pixel buffers that will never be needed again.

Canvas-Based Textures

Scene background and drop shadow are painted onto HTML <canvas> elements at startup and wrapped in CanvasTexture. No image files to fetch, no shadow render pass, no extra draw calls per frame.

Debounced Resize Handler

Waits 100 ms after the final resize event before recalculating aspect ratio and renderer dimensions. Without debouncing, dragging a window border fires hundreds of events per second, each triggering a full GPU resize.

will-change: transform

Applied to animatable card and gallery elements. This CSS hint promotes them to their own compositor layer before any interaction, so hover transforms are handled by the GPU compositor rather than triggering a CSS repaint.
